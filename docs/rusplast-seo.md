# Публикация статей РУСПЛАСТЗАВОДА

Оператор `rusplast-seo` добавляет одну новую статью каждые четыре дня в 12:00
по Москве. После успешной публикации следующая назначается через четыре дня.
Если Mac спал, приложение обрабатывает только актуальный выпуск: пропущенные
статьи не публикуются пачкой, интервал считается от фактической публикации.

Конфигурация: `operators/rusplast-seo.md`. Обработчик: `operator_app/seo.py`.
Статус, ход работы, ошибка, исходный контекст, статья, проверка и квитанция
публикации доступны в обычной истории Артель Оператора.

## Процесс

1. `scripts/editorial-context.mjs` сайта получает актуальный ассортимент из API,
   перечень прежних статей и разрешённые фотографии. Непроверенные рекламные
   описания и утверждения о пожарной безопасности не попадают в контекст автора.
2. Локальный Codex CLI, уже авторизованный через ChatGPT, выбирает новый вопрос
   покупателя и создаёт статью JSON. Нет фиксированного банка готовых текстов.
3. Структурная проверка контролирует дату, автора, метаданные, ссылки, изображения,
   точные выдержки источников и повторение запросов/заголовков. Отдельная сессия
   Codex проверяет факты, расчёты, пользу и пересечение с существующими статьями.
   Это автоматическая редакторская проверка, а не подтверждение живого эксперта.
4. Publisher выполняет `--validate-only`. Лишь успешно проверенный JSON сохраняется
   в таблице `seo_editions` SQLite как подготовленный выпуск. Повтор после сбоя
   использует именно его, включая неизменный slug и содержание.
5. Проверяются публичные ссылки; фиксированный `scripts/publish-article.py` сайта
   собирает страницы, проверяет SEO, сохраняет резервную копию и развёртывает web.
   Контракт ответа: `{url, slug, sha256, release}`. Оператор сверяет канонический
   SHA-256 JSON и фактический HTML опубликованной статьи. Только тогда статус готов.

## Условия работы

Mac включён и доступен интернет. LaunchAgent `ru.artel.operator` должен работать;
панель — http://127.0.0.1:8790. Действуют вход ChatGPT в Codex и SSH-доступ к серверу.
Генерация расходует лимиты подписки ChatGPT. Дополнительный API-ключ не создавался.
Этот процесс работает локально, не является серверным сервисом генерации.

Генератор запускается с ограничением времени и read-only sandbox. Он не получает
пароли и не выполняет публикацию. Для этого существует отдельный фиксированный
publisher. Данные GloPro/Яндекса не передаются в контекст статьи.

## Повтор после ошибки

Для сетевых проверок предусмотрено до трёх попыток. Если они не помогли, закончились
лимиты или редакторская проверка отклонила статью, запуск отмечается ошибкой.
Бесконечных автоматических повторов нет: после устранения причины нажмите запуск
оператора в панели за текущую дату. Один выпуск не создаёт повторную статью.
Если сайт уже принял JSON, но финальная проверка прервалась, повтор сверит ту же
публикацию. Не удаляйте состояние `data/operator.sqlite3` для повторного запуска.
Журнал самого сервиса: `data/logs/service.log` и `data/logs/service-error.log`.
Содержимое SSH/провайдерских ошибок не выводится в панель, чтобы не раскрыть
служебные данные; панель сохраняет этап, код сбоя и все уже подготовленные файлы.

Проверка Python: `.venv/bin/python -m pytest -q`. Импорт XLSX для SEO не используется.
