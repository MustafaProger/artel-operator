# Исправление нулевых отмен Яндекса — 29.09.2026

Причина остановки недельной выгрузки за 22–28.09.2026 подтверждена в действующем
кабинете ООО НК АРТЭЛЬ через сохранённую сессию. Полная выдача содержит 18 заказов:
15 `Completed`, два `StationCanceled` и один `UserCanceled`. У всех трёх отменённых
заказов `liters_filled = 0.0`, `final_price = 0.0`, валюта RUB. Старый код разрешал
только `Completed` и `Cancelled` и останавливался на первой штатной отмене.
Интерфейс самого кабинета отображает оба обнаруженных статуса как «Отменен».

В манифесте сохраняются исходные статусы и ID всех заказов. Новые статусы отмены
принимаются только при одновременно нулевых литрах и стоимости. Такие заказы
не увеличивают сумму закупки и литры. Ненулевые отмены, неизвестные статусы, возвраты и любые
расхождения продолжают блокировать публикацию. Сообщение ошибки содержит ID
проблемного заказа и конкретную причину без телефона или имени сотрудника.

После исправления полная выборка прочитана дважды: результаты совпали, 18 заказов
на одной терминальной странице, три сотрудника.

Следующий полный запуск `0f01557e0e434dddb8c47a7bcdecd50c` обнаружил вторую
особенность: Excel Яндекса исключает эти нулевые отмены. Его новый исходник
`a1feee4a727abe9ed3fd129d8b189cc2` восстановлен из кабинета без создания ещё одного
отчёта в `work/yandex-recovery-20260929/` с правами 0600. В API для сотрудника
14 заказов, в Excel 12. Все 12 завершённых заказов совпали построчно, сумма
346 890,27 руб., литраж 3 837,19 л. Лишних заказов нет. Отсутствуют исключительно
нулевые `UserCanceled` и `StationCanceled`.

Эти два подтверждённых типа нулевых отмен разрешено не включать в XLSX, только
если совпадает `user_id` сотрудника. Они сохраняются в аудите отдельно в
`cabinet_only_zero_cancellations`, а `cabinet_order_count` отражает полный API.
`order_count` и `orders` продолжают отражать фактический состав исходного Excel.
Пропуск любого `Completed`, даже с нулевыми значениями, любого неподтверждённого
статуса или ненулевой операции блокирует результат. Полная API-выборка по-прежнему
повторяется перед завершением. Восстановленный реальный исходник прошёл новую
проверку против всех 14 ожидаемых заказов.

Дополнительно в действующем кабинете обнаружен рекламный блок «Скидка 5% на мойки»,
перекрывающий кнопку «Отчёты» и не закрывающийся по Escape. Штатная клавиатурная
активация точных кнопок «Отчёты» и «Скачать» проверена в кабинете и используется
вместо клика мышью. Оферты автоматически не принимаются. Если скачанный исходник
не прошёл проверку, он сохраняется в подкаталоге `На проверку/<report_id>.xlsx`
с правами 0600; событие запуска содержит его путь. Итог при этом не публикуется.

В выгрузку и подключение Яндекса включён общий `browser_proxy` для адресов Яндекса
и его статических ресурсов. Системные сетевые настройки не изменяются. Проверка
кабинета и обе выборки успешно прошли через этот механизм; секреты сессии в аудит
и этот документ не записываются.

Проверки: `RUN_BROWSER_TESTS=1 .venv/bin/python -m pytest -q tests/test_yandex.py
tests/test_yandex_dynamic.py tests/test_yandex_browser.py` — 92 passed. Добавлены
регрессии на сохранение всех трёх видов нулевой отмены, пропуск сотрудников только
с отменами, блокировку каждой ненулевой комбинации литров/стоимости и сверку Excel
с завершённым и отменённым заказами. Подмена отмены завершённым статусом также
блокируется. Дополнительно проверены допустимые пропуски нулевых отмен, блокировка
пропусков обязательных заказов, сохранение отклонённого исходника и открытие
отчётов при перекрывающем кнопку рекламном блоке. `git diff --check` прошёл.
