Сотрудники берутся из полной выборки заказов недели по внутреннему `user_id`; активный справочник не запрашивается. Один ID с историческими именами остаётся одним сотрудником, разные ID с одинаковыми именами не объединяются. При совпадении имён исходники и разделы получают полный идентификатор.

Используется тот же сохранённый вход кабинета. Организация проверяется и в интерфейсе, и в ответе `/corp-cabinet/1.0/clients`; у каждого заказа сверяется `client_id`. Создание отчёта требует отдельного `x-idempotency-token`; каждый запрос создаёт новый отчёт с проверкой возвращённого ID, состояния готовности и скачанного содержимого. Старые файлы не подставляются.

Выборка `/corp-cabinet/2.0/orders/tanker/list` отправляется без фильтра сотрудников, статусов и активного справочника. Интервал включает 23:59:59.999999 последнего дня, UTC+3. Все курсоры проходят до терминальной страницы; проверяются схема, размер страницы, повтор курсора/заказа, порядок дат и доступное объявленное количество. Полная страница без следующего курсора считается неподтверждённой. После скачивания всех файлов вся неделя читается заново: изменение любого заказа блокирует публикацию. Метаданные организации, недели, UTC+3, количества заказов и обе итоговые суммы также сверяются. Яндекс округляет «Залито» в XLSX до сотых: фактическая строка API 48.037 соответствует 48.04 в Excel. Сверка учитывает это округление отдельно для каждой строки (HALF_UP); итог считается из строк Excel. Стоимость сверяется точно. Коэффициенты GloPro не применяются.
