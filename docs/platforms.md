# Платформы автоматизации: исследование 19.09.2026

Это исторический срез на 19 сентября. Актуальная сверка реализации, ограничений и проверок: [аудит 24.09.2026](architecture-review-2026-09-24.md). Последующие живые проверки описаны в [GloPro 22.09](glopro-weekly-2026-09-22.md) и [Яндекс 22.09](yandex-verification-2026-09-22.md); прежние ограничения ниже не следует считать автоматически актуальными.

Для первого оператора выбран самостоятельный Python-сервис: настройки в Markdown/YAML, браузерный адаптер, расчёты в коде, проверка результата и готовые файлы. Такой модуль впоследствии можно запускать из внешнего оркестратора.

## Что подтверждено по GloPro

[Официальное описание системы (PDF)](https://glopro.ru/files/Service_desribe_on_site.pdf), страницы 4–6, описывает API для внешних систем, HTTPS GET/POST и файловый обмен xls/csv/json/txt. Это не подтверждает API-доступ конкретного аккаунта. Публичная спецификация endpoint/auth в просмотренных источниках не найдена.

[Личный кабинет](https://glopro.ru/personal-account/) подтверждает отчётность и выгрузку в учётные системы. [Клиентский кабинет](https://glopro.ru/client-account/) перечисляет клиентский отчёт и отчёт по картам; набор отчётов может отличаться у заказчиков.

[Инструкция GloPro](https://glopro.ru/files/instruction.pdf) индексируется поиском. По поисковому фрагменту раздел 4.5.2.3 описывает выгрузку в 1С с предварительно согласованным форматом и выбором фирм/договоров. Полный PDF в ходе исследования через web.open не загрузился, поэтому это ограниченное подтверждение.

## Ограничения текущего браузерного адаптера

Адаптер открывает «Фирмы», перебирает доступные фирмы и договоры, проверяет вкладку «Счет», затем формирует «Транзакционный отчет со скидкой» во вкладке «Отчеты». Набор недавних операций на счёте не используется для исключения фирмы: расчёт опирается на XLSX за точный период. Каждому источнику присваиваются ID фирмы и договора. Для нескольких договоров оригиналы сохраняются по папкам «Договор ID», сохраняя в имени файла название фирмы.

Полнота списка фирм подтверждается ответами `/clients/clients-list`: непрерывная цепочка `offset` от нуля, конечное `data.more=false` и совпадение всех ID/названий с отрисованными карточками. Схема проверена в опубликованном самим GloPro `/assets/build/js/site.js`: `success`, `data.items`, `data.more`, необязательный `data.count`. Исчезновение кнопки загрузки само по себе не является подтверждением полноты. Проверка счёта сохраняет видимые даты из загруженного раздела, помечая их как ограниченный предварительный просмотр.

Проверка подключения текущим адаптером 19.09.2026 подтвердила 32 фирмы за 33,7 секунды, включая непрерывность ответов пагинации и соответствие DOM. Первый переход занял 22,9 секунды и потребовал повтор; перезагрузка списка — 2 секунды. Это подтверждает работоспособность подключения и полного списка, но не завершение выгрузки отчётов для всех фирм.

Прямое скачивание шаблона со скидкой проверено на живом кабинете для ООО «УНИСТРОЙ» за 15–17.09.2026. Полученная книга соответствует ожидаемым колонкам J/M/P/S. Полный прогон всех фирм и отдельная проверка ООО «Спайка-Север» на этой стадии ещё не завершены.

При диагностике встроенный Chromium периодически зависал после TLS ClientHello: DNS и TCP устанавливались за 2 мс, затем за 10 секунд не поступало ни одного байта ответа. Это сетевой этап до HTTP, авторизации и обработки страницы; конкретная внешняя причина не установлена. Установленный Google Chrome в отдельном временном контексте успешно открыл публичный кабинет за 2,1 секунды. Поэтому на macOS адаптер выбирает `/Applications/Google Chrome.app`, если он установлен, иначе — встроенный Chromium. Можно явно задать `GLOPRO_BROWSER_CHANNEL=chrome` или `chromium`. Ограничение версии TLS удалено; проверка сертификата включена. Профиль, cookies и пароли обычного браузера пользователя не читаются: для каждого запуска создаётся отдельный временный контекст. Успешная загрузка входной страницы сама по себе не подтверждает завершение всех выгрузок.

Последующий запуск Chrome из приложения также столкнулся с зависанием. Отдельный публичный тест того же контекста через `route.fetch` открыл GloPro с HTTP 200 за 4,12 секунды, включая загрузку скриптов и стилей; сам документ получен за 0,94 секунды. Теперь для точного origin `https://lk.glopro.ru` по умолчанию применяется транспорт Playwright API: `route.fetch(max_redirects=0, max_retries=0, timeout=20000)` и `route.fulfill(response=...)`. Редиректы остаются браузеру, POST не повторяется, ответ освобождается после передачи. Ошибки транспорта не выводят исходные логи, которые могут содержать данные формы. Неиспользуемые изображения/шрифты/медиа и трекеры блокируются до отправки. Явный `GLOPRO_TRANSPORT=direct` возвращает обычный транспорт браузера. Тест этого механизма пока подтверждает публичную страницу; авторизация и полный прогон должны быть проверены отдельно.

Официальная документация: [Route.fetch](https://playwright.dev/python/docs/api/class-route#route-fetch) описывает отключение редиректов и повторов; [APIRequestContext](https://playwright.dev/python/docs/api/class-apirequestcontext) описывает общий cookie jar с текущим браузерным контекстом. Сессия не экспортируется на диск.

Переходы на страницы имеют два ограниченных повтора при сетевой ошибке. Команда формирования отчёта отправляется один раз. Если вместо файла GloPro переводит отчёт в отдельную очередь, для которой ещё не проверен интерфейс, запуск завершится ошибкой. Старые файлы не подставляются вместо нового отчёта. Адаптер не активирует, не блокирует карты и не меняет лимиты.

Проверки адаптера в tests/test_glopro.py выполняются офлайн: даты, полнота страниц клиентов, дубликаты, выбор по ID, имена файлов (включая длинные названия кириллицей), происхождение скачивания и целостность XLSX. Они не заменяют полный прогон живого кабинета.

Последняя проверка 19.09.2026: полный запуск с API-транспортом остановился при открытии `/`. После этого обновление уже открытого кабинета в пользовательском Chrome тоже показало `ERR_TIMED_OUT`. Поэтому причина не сведена к встроенному Chromium и не объявлена устранённой. Расписание приложения включено по запросу пользователя; успешный полный комплект ещё не подтверждён.
