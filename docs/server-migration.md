# Подготовка переноса на сервер

Состояние: подготовка к развёртыванию; серверная выгрузка и SEO ещё не проверены.

## Что готово

- Базовый Docker-образ: Python, приложение, Chromium и его зависимости.
- Данные и настройки сохраняются снаружи контейнера; порт только 127.0.0.1.
- Compose по умолчанию выключает расписание через OPERATOR_SCHEDULER_ENABLED=false.
  Ручные запуски остаются доступны и выполняют реальные действия.
  Локальный запуск без этой переменной сохраняет прежнее поведение.
- Выбранные Markdown-файлы из knowledge подключаются к SEO через knowledge_files.
  Автор и редактор получают один снимок; context.json содержит текст и SHA-256.
  Правила проверки фактов по CMS не заменяются заметками. Подробнее: knowledge/README.md.

## Порядок переноса

1. Выбрать сервер и настроить SSH. Проверить доступ с сервера к GloPro, Яндексу,
   CMS и используемым сервисам OpenAI. Назначить место резервных копий.
2. Скопировать код и отдельные серверные настройки operators. На серверной копии
   убрать пути /Users/... и network_interface: en0. Для SEO указать реальные
   пути site_root, codex_path, node_path, python_path. obsidian_output удалить
   либо заменить доступным серверным каталогом. Локальные настройки сохранить.
3. Дождаться завершения локальных заданий, остановить локальный процесс и сделать
   согласованную резервную копию всего data и operators; перенести данные через SSH.
   Не копировать работающую SQLite как обычный одиночный файл.
4. Подготовить папку knowledge с выбранными заметками и перечислить их в
   knowledge_files серверного SEO-оператора. Секреты туда не помещать: контекст
   доступен в архиве отчёта. iCloud автоматически не синхронизируется.
5. Запустить `docker compose up -d --build`. Расписание пока выключено.
   На Mac открыть `ssh -L 8791:127.0.0.1:8790 USER@SERVER`, затем
   http://127.0.0.1:8791. Проверить полный ответ интерфейса и историю.
6. Проверить GloPro и Яндекс реальными согласованными выгрузками. Проверить архивы
   и расчёты. Для повторного входа в Яндекс потребуется отдельное решение:
   текущая кнопка запускает графический браузер на хосте приложения.
7. Подготовить отдельное окружение SEO: базовый образ НЕ содержит Codex, Node,
   проект сайта, SSH-настройки и авторизацию. Настроить их, проверить генерацию
   текста и изображения, проверки и доступ к CMS. Вход ChatGPT и API-ключ — разные
   варианты; совместимость встроенного image_gen нужно подтвердить на сервере.
8. Перед включением расписания проверить ближайшие даты и возможное выполнение
   пропущенных заданий. Убедиться, что локальный планировщик остановлен.
   На сервере задать OPERATOR_SCHEDULER_ENABLED=true в .env и выполнить
   `docker compose up -d`. Проверить первый плановый результат и резервное копирование.

## Что ещё не сделано

Выбор/подключение сервера, серверный SEO runtime и вход, перенос данных,
повторная авторизация Яндекса без локального окна, выбор самих заметок,
их автоматическая синхронизация, резервное копирование по расписанию и
проверка восстановления, сквозная серверная проверка. До этих проверок перенос
не считается завершённым. Эта инструкция не включает публичный доступ по домену.
