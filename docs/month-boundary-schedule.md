# Календарь актирования на границе месяцев

Правило включено только в текущем операторе GloPro через YAML:

```yaml
schedule:
  days: [tue, fri]
  time: '07:00'
  timezone: Europe/Moscow
  month_boundary: close_previous_month
  month_boundary_from: '2026-09-29'
```

Дата включения сохраняет прежний расчёт старых плановых дат. Алгоритм не содержит
исключений для октября 2026 года. Без этих параметров действует прежний календарь.
Этот режим разрешён только для GloPro с обоими днями (вторник и пятница) по Москве.

## Обычные фирмы

Базовые интервалы: вторник за пятницу–понедельник; пятница за вторник–четверг.
Если такой интервал содержит дни двух месяцев, соответствующий запуск переносится
на 1-е число нового месяца. Он закрывает остаток прошлого месяца, а исходный обычный
запуск отменяется. Следующий обычный запуск начинается с 1-го числа. Дата выполнения
не означает, что операции этого дня уже включены в закрывающий отчёт.

Первое число используется в любой день недели, включая выходные (подтверждено
пользователем). Если первое число уже вторник или пятница, сохраняется обычный
запуск за конец предыдущего месяца. Время всех запусков берётся из schedule.time.

| Дата актирования | Период обычных фирм, включительно |
| --- | --- |
| Вторник 29.09.2026 | 25–28 сентября |
| Четверг 01.10.2026 | 29–30 сентября |
| Пятница 02.10.2026 | Перенесено на 1 октября, отдельного запуска нет |
| Вторник 06.10.2026 | 1–5 октября |

Начало 25 сентября следует из базового правила вторника: отчёт за пятницу–понедельник.

## Недельные фирмы и другие операторы

Китай (78749) и ООО «НК АРТЭЛЬ» (78756) сохраняют каждый вторник за предыдущие
вторник–понедельник. Месячные переносы не делят их недельный интервал. Если обычный
вторник переносится, во вторник остаётся запуск только этих фирм; он не сдвигает
начало следующего обычного периода. Если обе фирмы исключены или не входят в
ограниченный список clients, такой дополнительный запуск отсутствует.

Например, при 1 ноября в воскресенье: обычное закрытие 1 ноября за конец октября;
3 ноября — только недельные фирмы; 6 ноября — обычные фирмы за 1–5 ноября.

Яндекс сохраняет недельное актирование, SEO — своё интервальное расписание.
У других определений операторов календарь автоматически не включается.

## Единая модель

`run_plan(conf, day)` возвращает дату запуска, основной период и отдельно обычный
и недельный интервалы, тип запуска и исходную дату переноса. `schedule_matches`,
`next_run`, `latest_run_date` и расчёт клиентского периода используют ту же модель.
Недопустимая дата сообщает дату переноса и следующий доступный запуск.

Периоды и настройки выполненного запуска сохраняются в его истории. Повтор
использует сохранённый план. Изменение текущего календаря не переопределяет
периоды ранее обработанных файлов.

Снимок содержит календарные периоды отдельно от списка выбранных фирм. Если
список расширить, добавленные обычные или недельные фирмы получат соответствующий
период того же сохранённого календаря. Частичный импорт не считается полным
выполнением автоматического запуска. Успешный ручной запуск с выгрузкой всех фирм
текущего списка заменяет автоматический запуск той же даты и учитывается в
карточке следующего запуска.

Старые записи остаются неизменными. Если ранее уже был сохранён запуск по старому
календарю и новый период другой даты с ним пересекается, программа сообщает о
конфликте до выгрузки. Такой случай требует сверки истории; периоды автоматически
не обрезаются по последнему успешному запуску, потому что он мог быть частичным.

Проверки охватывают согласованный пример, обычные недели, первое число во все дни
недели, выходные, Новый год, високосный февраль, включение правила, недельные фирмы,
неизменность Яндекса/SEO и непрерывность обычных периодов за несколько лет.
