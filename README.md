# Артель · Оператор

Приложение для автоматизации регулярных процессов Артели. Первый процесс: GloPro → XLSX по фирмам → проверяемый расчёт → архив с готовыми отчётами. Интерфейс на русском, настройки операторов в Markdown с YAML-блоком. Яндекс Заправки подключён через сохранённую сессию кабинета; для Лукойла сохранён шаблон.

Состояние на 22.09.2026: на этом Mac установлена служба, расписание — вторник/пятница 07:00 МСК. Китай и ООО «НК АРТЭЛЬ» возвращены в обработку по отдельным недельным правилам: только во вторник, за предыдущий вторник–понедельник. Для остальных фирм расчёты и периоды сохранены. Подробности: [недельные правила и проверка](docs/glopro-weekly-2026-09-22.md), [загрузчик](docs/glopro-download-check-2026-09-22.md).

## Локальный запуск

Нужен Python 3.12+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m uvicorn operator_app.main:app --host 127.0.0.1 --port 8790 --workers 1
```

Откройте http://127.0.0.1:8790. Файл `Открыть Артель Оператор.webloc` открывает интерфейс уже работающего приложения. Для ручного запуска без установленной службы есть `start.command`.

На macOS автоматизация использует установленный Google Chrome с отдельным временным профилем. Если Chrome отсутствует, используется Chromium из Playwright. Выбор можно явно задать через `GLOPRO_BROWSER_CHANNEL=chrome` или `chromium`. Проверка сертификатов включена.

Для HTTPS-запросов к `lk.glopro.ru` по умолчанию используется транспорт Playwright API (`GLOPRO_TRANSPORT=api`): он возвращает ответы тому же браузерному интерфейсу и сохраняет его временную сессию. Через него 22.09.2026 подтверждены вход, полный список фирм и выгрузка 32 XLSX. Переходы после ответов 3xx обрабатывает браузер; POST-запросы автоматически не повторяются. Режим `GLOPRO_TRANSPORT=direct` явно включает обычный браузерный транспорт. Эти настройки читаются при запуске задания; для переменных окружения службы нужен её перезапуск.

Автозапуск приложения при входе в macOS и восстановление после сбоя:

```sh
.venv/bin/python install_macos_service.py
```

Перед установкой службы остановите ручной экземпляр на порту 8790. Для удаления службы используйте `--remove`; файлы и история сохраняются. Служба macOS не включает и не пробуждает выключенный или спящий компьютер.

В разделе «Подключение» сохраняется логин GloPro. Данные лежат только в `data/credentials.json` с правами `0600`, каталог `data` имеет права `0700`; это файл с ограничением доступа, а не шифрование. Он исключён из Git и Docker-образа. Можно вместо файла передать `GLOPRO_USERNAME` и `GLOPRO_PASSWORD` через окружение службы. Интерфейс не возвращает пароль.

Программа слушает только localhost. От другого сайта нельзя менять настройки, запускать задания или читать данные через браузер. Не публикуйте порт напрямую в интернете. Для сервера предусмотрен доступ через SSH-туннель.

## Расписание

Настройка `operators/glopro.md`: вторник и пятница, 07:00, Europe/Moscow. Цель — завершить к 08:00; час оставлен на выгрузку и проверку, но доступность кабинета и время выгрузки не гарантируются. Для обычных фирм во вторник период пятница–понедельник, в пятницу — вторник–четверг. Для Китая и ООО «НК АРТЭЛЬ» только во вторник: предыдущий вторник 00:00:00 — понедельник 23:59:59 по Москве; в пятницу они пропускаются. Повтор привязан к плановой дате, включая границы месяца и года. Даты включены полностью. Ручной запуск в другой день берёт последнюю плановую дату, её можно изменить на нужный вторник или пятницу.

Для включения в Markdown установите `enabled: true`. Неактивный оператор допускает ручной запуск для проверки. Встроенный планировщик работает только вместе с процессом приложения. Он записывает запуск в SQLite до выполнения, не создаёт дубликат по расписанию и после перезапуска проверяет пропущенные даты за последние 7 дней, начиная с момента включения. Прерванное выполнение отмечается ошибкой, повтор доступен вручную.

Закрытый или выключенный Mac не выполняет задания. Для независимого расписания установите приложение на постоянно работающем сервере.

```sh
docker compose up -d --build
```

Compose публикует порт только на loopback сервера. На своём Mac откройте туннель:

```sh
ssh -L 8790:127.0.0.1:8790 USER@SERVER
```

Затем используйте http://127.0.0.1:8790. Серверный Docker-вариант подготовлен; факт успешной локальной проверки не означает развёртывание на сервере.

## Файлы и расчёты

Каждый запуск имеет отдельный каталог `data/runs/<id>`. Оригиналы называются по фирмам — `ООО "НАЗВАНИЕ".xlsx`. Даты входят в название общего ZIP. В готовом комплекте — исходные XLSX, итог Markdown/TXT, сводный Excel, снимок инструкции и JSON с проверкой расчётов/контрольными суммами.

При нажатии «Сформировать» GloPro открывает запрос отчёта в новой вкладке и возвращает файл для скачивания. Оператор ожидает именно этот файл и сверяет параметры запроса: фирму, договор, шаблон, период и XLSX. История «Заказанных отчётов» загружается отдельно и не используется для выбора файла. Если новое скачивание не подтверждено, запуск завершается ошибкой; старый отчёт не подставляется.

До формирования XLSX проверяются последние операции выбранного договора. При подтверждённом отсутствии заправок за период файл не запрашивается: фирма попадает в список «Без заправок». Этот endpoint GloPro возвращает только последние десять операций: `more: false` не доказывает полноту истории. Если окно не достигает нужного периода, запуск останавливается с объяснением, а не выдаёт пустой или неполный отчёт. Неизвестный ответ или ошибка сервиса также не считаются отсутствием операций. Если все выбранные фирмы проверены и пусты, результат — «Нет операций».

Фирмы сортируются по полному названию в русском алфавитном порядке, без учёта регистра, кавычек и различия «ё»/«е»: при выгрузке, в Markdown/TXT, сводном Excel, обновляемой заметке Obsidian. Суммы и текст чужих разделов заметки сохраняются при перестановке.

Отправка в Telegram отменена по запросу пользователя 22.09.2026 и удалена из приложения. Готовые файлы доступны в истории запусков.

## Яндекс и общие шаблоны

[Шаблоны топливных отчётов](docs/fuel-report-templates.md) и исходная инструкция Obsidian дополнены правилами Яндекса и закупки Лукойла на склад. Яндекс актируется только во вторник за предыдущий вторник–понедельник, UTC+3, отдельно по всем сотрудникам с заправками. Для запуска 22.09.2026 это 15–21.09.2026. Литры и закупка берутся из исходного отчёта, коэффициенты GloPro к ним не применяются.

Состав сотрудников определяется по всем заказам недели, с проверкой курсорной пагинации и повторной сверкой после выгрузки. Активный справочник и `employee_aliases` не ограничивают выборку. Одноимённые сотрудники разделяются по `user_id`; файлы при совпадении имён содержат ID.

Автоматическая выгрузка реализована через кабинет Яндекс Go: однократный вход в «Подключения → Яндекс Заправки», затем работа по сохранённой локальной сессии. API-ключ для этого способа не нужен. Срок действия входа определяет Яндекс; при повторном запросе авторизации нужно снова подключить кабинет. Литры берутся из «Залито», сумма закупки из «Стоимость»; «Запрос» не равен фактическому литражу. Импорт поддерживает проверенную XLSX-выгрузку кабинета с листом «Отчёт», реквизитами периода и итогами. Скриншот и пример суммы не заменяют исходный Excel.

`excluded_clients` в `operators/glopro.md` задаёт временные исключения объектами `{id, name}`. Автоматические запуски пропускают эти ID до открытия договоров и формирования отчётов. Сейчас список пуст. Для ООО «НК АРТЭЛЬ» (78756) и «Китай» (78749) действуют отдельные недельные правила. Исключения отражаются в деталях запуска и аудите. Политики двух недельных фирм реализованы в обработчике; их описание и шаблоны приведены в инструкции оператора.

Для двух недельных фирм проверяются период внутри Excel, подписанные операции, итоги услуг, карт и файла. Китай: литры J, поставщик M × 0,99 (три знака), клиент P (два знака). НК АРТЭЛЬ: группировка по держателю из Excel и топливу, J/P с двумя знаками. Обычные коэффициенты карт и бензина к ним не применяются, цена за литр в их шаблонах отсутствует.

Колонки определяются по заголовкам: `Количество`, `Стоимость ТО`, `Стоимость`, `Скидка, %`. ДТ и ДТ ЭКТО объединяются, возвраты учитываются со знаком минус. Расчёт использует Decimal. Цена поставщика вычисляется из Стоимости ТО; сумма клиента — отдельно из Стоимости. Коэффициенты и исключения заданы в YAML. При ошибке хотя бы одной фирмы итоговая активация не публикуется; исходники доступны с пометкой «На проверку».

Опциональный `obsidian_output: /абсолютный/путь/Работа` сохраняет готовый Markdown в Obsidian. Повтор обновляет разделы обработанных фирм в том же файле «Активация — ДД.ММ.ГГГГ.md», сохраняя остальные разделы; копии с суффиксом запуска не создаются. При ошибке сверки существующая заметка остаётся без изменений. На сервере это должен быть существующий смонтированный каталог; iCloud Mac не появляется там автоматически.

## Новые операторы

В интерфейсе можно создать новый Markdown-файл оператора. YAML меняет расписание, список фирм, коэффициенты и выходной каталог. Свободный Markdown хранит требования и включается в архив, но не превращается автоматически в новые действия.

Новый тип автоматизации подключается двумя независимыми Python-функциями в `operator_app.engine`:

- `HANDLERS[kind]` получает `(config, run_record, output_directory, progress_callback)` и возвращает список исходных файлов `[{"path": "..."}]` с необязательными метаданными. Для GloPro это выгрузка из кабинета.
- `PROCESSORS[kind]` получает `(config, run_record, sources, output_directory, progress_callback, *, imported)` и возвращает `ProcessResult`. Он проверяет исходники, создаёт свои итоговые файлы в каталоге запуска и задаёт `status`, `report`, `error`, `metrics`, `audit`. Допустимые статусы — `completed`, `needs_review`, `no_data`. Чужому оператору топливный калькулятор не навязывается.

Пример возвращаемого результата другого обработчика:

```python
from operator_app.engine import ProcessResult

def process_documents(config, run_record, sources, output_directory, progress, *, imported):
    # Здесь проверка конкретных документов и создание итоговых файлов.
    return ProcessResult(
        status="completed",
        report="Проверено два документа",
        metrics={"document_count": 2},
        audit={"checked_documents": 2},
    )
```

Обе функции нужно зарегистрировать при запуске приложения: `HANDLERS["documents"] = download_documents`, `PROCESSORS["documents"] = process_documents`. Общий исполнитель сохраняет снимок Markdown, историю, контрольные суммы исходников, JSON проверки и ZIP. Процессор не может через `metrics` менять ID, период или системные поля запуска. GloPro уже использует этот же контракт.

Неподключённый тип сохраняется выключенным и не запускается. Для зарегистрированного типа доступен ручной запуск с `enabled: false`. Встроены GloPro, Яндекс Заправки и `seo` для РУСПЛАСТЗАВОДА: новый текст через локальный Codex, проверка фактов и повторяющихся тем, публикация на сайт каждые четыре дня. [Инструкция и условия SEO-процесса](docs/rusplast-seo.md). Для следующего типа по-прежнему нужно подключить обработчик, период и проверку подключения; произвольное расписание и авторизация сервиса не появляются из одного Markdown-файла. Форма импорта принимает XLSX только для топливных операторов.

Изменение лимитов карт, отправка писем и электронная подпись в текущий оператор не входят. «Активация» здесь — отчёт по инструкции.

## Проверка

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Для проверки скрытого переключателя XLSX и скачивания из новой вкладки в настоящем Chrome/Chromium:

```sh
RUN_BROWSER_TESTS=1 .venv/bin/python -m pytest -q
```

Браузерный тест использует локальную имитацию страниц GloPro, перехватывает все запросы и не обращается к кабинету. По умолчанию он пропущен, чтобы обычные тесты не требовали установленного браузера.

Тесты проверяют границы периодов, переход года, часовой пояс, возвраты, разделение сумм клиента и поставщика, исключения, неверный формат выгрузки и защиту от неполного результата. Исследование готовых платформ: `docs/platforms.md`. Проверка арифметики: `docs/calculation-audit.md`.

[Аудит и план развития от 24.09.2026](docs/architecture-review-2026-09-24.md) сопоставляет код с проверками и изученными модулями Prefect, APScheduler и LangGraph. Первый этап усиливает транзакционное резервирование запуска, завершение при отказе исполнителя/файлов и сохранение ручных разделов Obsidian. Стек, настройки, API и расчётные правила сохранены; миграция БД не требуется.

Яндекс: вторник 07:00 Europe/Moscow; повтор сохраняет плановую дату. Импорт отдельных XLSX проверяет только переданный комплект. В стандартном XLSX нет внутреннего `user_id`: для неизвестных сотрудников используется полный хеш телефона; неоднозначные привязки блокируются. Автоматическая выгрузка подтверждает личность и каждую операцию по `user_id` и ID заказа кабинета. [Проверка и ограничения](docs/yandex-verification-2026-09-22.md).
